DIR C:\Users\sdumont\AppData\Roaming - user-writable profile path; the payload iblenor.exe was dropped here (EID 11), so a new executable in this tree is the case's signature
DIR C:\Users\sdumont\AppData\Local\Temp - user-writable staging; droppers unpack here before moving and nothing legitimate persists in it
DIR C:\Users\sdumont\Downloads - arrival point; the lure PORTWAY-DISPATCH-UPDATE.js was executed from here (EID 1), so a new script here is how the next case starts
DIR C:\Users\Public - writable by any local user with no profile needed; shared drop location used when the user's own directory is being watched
DIR C:\ProgramData - broadly writable staging used by deployment tooling and attackers alike, so changes here must be attributable to a package
DIR C:\Users\sdumont\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup - per-user autostart; anything placed here runs at logon without privilege
DIR C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup - all-users autostart, the same primitive with a wider blast radius
DIR C:\Windows\System32\Tasks - scheduled-task store; persistence that survives a reboot without a service account
KEY HKLM\Software\Microsoft\Windows\CurrentVersion\Run - machine-wide autorun; the strongest Run-key primitive on the host
KEY HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce - machine-wide one-shot autorun; typical staging of a second stage
KEY HKCU\Software\Microsoft\Windows\CurrentVersion\Run - per-user autorun; the intrusion wrote Tavistock9 here pointing at iblenor.exe, so this key is mandatory
KEY HKEY_USERS\*\Software\Microsoft\Windows\CurrentVersion\Run - the same key family across every loaded hive, so a write in any profile is seen
CHECK Sysmon EID 1 process creation with command line - lineage is decided by parent image and command line; without them powershell.exe looks identical on both chains
CHECK Sysmon EID 11 file creation with hashes - a dropped binary is evidence only if its hash is pinned to the ProcessGuid that wrote it
CHECK Sysmon EID 13 registry value set - autorun persistence is a registry value and no other stream shows it being set
CHECK Sysmon EID 3 network connection with destination hostname - the C2 is identified by where a process talked, not by its name
CHECK Windows audit policy, process creation with command line - so the trail survives the agent being uninstalled or the host being re-imaged
Scope boundary: whole disk, C:\Windows\System32, C:\Program Files and the system hive are deliberately not monitored, because they change on every patch cycle, bury the signal and cost the endpoint.
