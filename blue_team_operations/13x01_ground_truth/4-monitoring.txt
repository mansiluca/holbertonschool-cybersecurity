Monitoring decision, one entry per line, each tied to an artefact from this case.

DIR C:\Users\sdumont\AppData\Roaming - this is exactly where the compromise put iblenor.exe (EID 11, ProcessGuid {a0e0be61-dffb-40af-9c7b-f0a6c40d4ea5}), so a new executable in this tree is the same move repeated
DIR C:\Users\sdumont\AppData\Local\Temp - droppers stage here between download and execution; nothing legitimate on a dispatch workstation persists in it
DIR C:\Users\sdumont\Downloads - the lure PORTWAY-DISPATCH-UPDATE.js was executed from here at 07:55:00, so a new script in Downloads is how the next case starts
DIR C:\Users\Public - writable by any local account with no profile; the shared drop used when the user's own AppData is being watched
DIR C:\ProgramData - writable staging shared by the Northmoor deployment agent and by attackers, which is why a change here must be attributable to a package like pkg_7708
DIR C:\Users\sdumont\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup - per-user autostart, runs at logon with no privilege; an alternative persistence path to the one actually used
DIR C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup - all-users autostart, the same primitive as the Tavistock9 Run value but louder and wider
DIR C:\Windows\System32\Tasks - scheduled-task store; seven tasks already predate the incident window, so additions or edits are the change worth seeing
KEY HKCU\Software\Microsoft\Windows\CurrentVersion\Run - the intrusion wrote Tavistock9 here pointing at AppData\Roaming\iblenor.exe at 07:55:14.051; this key is the case
KEY HKLM\Software\Microsoft\Windows\CurrentVersion\Run - machine-wide autorun, the strongest Run-key primitive; a value here would survive every profile on the workstation
KEY HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce - one-shot machine autorun, the usual place a second stage is staged
KEY HKEY_USERS\*\Software\Microsoft\Windows\CurrentVersion\Run - the same key across every loaded hive, so a persistence write in another profile is not invisible
CHECK Sysmon EID 1 with command line - the two powershell.exe processes in this case are identical in image and MD5 (121E1253E10DBE8D2D06AAE33EDBC859); only the parent image and command line separate the lure chain from the deployment chain
CHECK Sysmon EID 11 with hashes - iblenor.exe is evidence because its hash is pinned to the ProcessGuid that wrote it, not because of its name
CHECK Sysmon EID 13 - the Tavistock9 Run value exists only in this stream; file monitoring alone would have missed the persistence entirely
CHECK Sysmon EID 3 with destination hostname - the two chains differ by where they talked: 198.51.100.47 externally versus 10.42.8.0/24 internally, and pkg_7714 was decided on that single connection
CHECK Windows audit policy, process creation with command line - so the trail survives the agent being uninstalled or the host being re-imaged
SCOPE DECISION: eight directories, four Run-key families and five event/audit checks - every one of them a place this incident used or would have used
NOT MONITORED: whole disk, C:\Windows\System32, C:\Program Files and the system hive - they change on every patch cycle, they would bury the Tavistock9 signal in update noise, and integrity there is patch management's job
