C:\Users\*\AppData\Roaming is monitored because the payload iblenor.exe was written there (EID 11), so a new executable in any profile's roaming folder is this case repeating itself
C:\Users\*\AppData\Local\Temp is monitored because droppers stage here between download and execution, and no legitimate dispatch software persists in a temp directory
C:\Users\*\Downloads is monitored because the lure PORTWAY-DISPATCH-UPDATE.js was executed from this folder at 07:55:00, which is how the intrusion entered
C:\Users\Public is monitored because it is writable by any local account without a profile, so it is the shared drop used when the user's own folder is being watched
C:\ProgramData is monitored because the Northmoor deploy agent and an attacker both stage there, so a change must be attributable to a package such as pkg_7708
C:\Users\*\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup is monitored because it is per-user autostart that needs no privilege, an alternative to the Run key that was actually used
C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup is monitored because it is the all-users autostart, the same primitive with a wider blast radius
C:\Windows\System32\Tasks is monitored because seven scheduled tasks predate the incident window, so an addition or an edit is the change worth seeing
HKCU\Software\Microsoft\Windows\CurrentVersion\Run is monitored because the intrusion wrote Tavistock9 there pointing at iblenor.exe at 07:55:14.051
HKLM\Software\Microsoft\Windows\CurrentVersion\Run is monitored because it is the machine-wide autorun and would survive every profile on the workstation
HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce is monitored because it is the one-shot machine autorun, the usual place a second stage is staged
HKEY_USERS\*\Software\Microsoft\Windows\CurrentVersion\Run is monitored because the same key exists in every loaded hive, so a write in another profile is not invisible
Sysmon EID 1 with command line is enabled because both powershell.exe processes carry the same image and MD5 121E1253E10DBE8D2D06AAE33EDBC859, and only the parent image and command line separate them
Sysmon EID 11 with hashes is enabled because a dropped binary is evidence only when its hash (iblenor.exe, SHA-256 d13e0265140f33bc79de76e6c31708138443510e9d44184f5acd44ea7a88c6b2) is pinned to the ProcessGuid that wrote it
Sysmon EID 13 is enabled because the Tavistock9 persistence value exists only in this stream, and file monitoring alone would have missed it
Sysmon EID 3 with destination hostname is enabled because the two chains differ by where they talked, 198.51.100.47 externally against 10.42.8.0/24 internally, which is what decided pkg_7714
Windows audit policy for process creation with command line is enabled because the trail must outlive the agent being uninstalled or the host being re-imaged
C:\Windows\WinSxS, C:\Windows\SoftwareDistribution and C:\Windows\servicing are not monitored because they change on every patch cycle and would bury the Tavistock9 signal; the scope stays at nine paths, four registry locations and five event checks
